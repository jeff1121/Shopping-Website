# 只使用單一 Azure 環境

專案只建立一個 Azure 環境，先試運行、之後直接轉入正式營運；轉換時只由人工更換 Key Vault 中的敏感設定，不重建資源。沒有獨立的測試環境，也不使用 staging slot。原因是這是個人維護的小型專案，成本與維運負擔優先，而且轉換只需要換密碼。

## Consequences

- 新版本無法先在獨立環境驗證，品質閘門只有 PR 檢查與部署後的冒煙測試；失敗時以重新部署上一版 `site.zip` 回滾。
- 資料庫 migration 必須只新增、不破壞，因為沒有另一個環境可以預演。
- 示範資料與正式資料共用同一個資料庫，轉入正式營運時必須人工清除示範資料。
